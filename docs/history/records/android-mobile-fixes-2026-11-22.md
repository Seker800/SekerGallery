# 安卓 0.9.28：4K 分享、操作回执与大图库效率修复

> 状态：历史记录 | 核验日期：2026-11-22 | 对应提交：本轮本地提交（见同批 `git log`）
>
> 依据 [手机端评审](../reviews/mobile-app-review-2026-11-22.md) 的 20 项问题逐项处理。只改代码、测试和文档；
> 未部署生产，未连接群晖或 SekerChat，未运行真机／模拟器设备套件。

## 1. 分享

- 图片默认走服务端 `share-image`（长边最多 4096、JPEG、去 EXIF），结果按 `assetId + mediaRevision`
  缓存在 `cacheDir/shared-media`；GIF／WebP 保留原字节，避免动画被压成静帧。
- 视频优先分享服务端 MP4 播放副本；没有播放副本时回退原件，并受 512 MiB 分享预算限制。
- 4K 生成失败时自动回退原图（仍受预算限制）；分享准备阶段显示“生成 4K／准备兼容视频／准备原文件”
  和已下载字节；分享缓存 7 天、原文件／视频临时目录 1 天清理。
- 手机网页 `navigator.share` 同样改用 4K 分享图；GIF／WebP／视频走原文件，并把“文件较大”与
  “环境不支持分享”分开提示。服务端返回分享图失败时，在文件不超过 32 MiB 时回退原文件。
- 大图底栏文案由“发送”改为“分享”，与选择栏“发送到素材／照片”区分。

## 2. 操作回执与列表一致性

- 回收站／恢复改走 `/api/{mode}/operations` 的 `TRASH`／`RESTORE`，不再受 `batch/trash` DTO 的 100 项限制，
  也不再只拿到 202 就显示“已完成”。
- 标签、评分、收藏请求解析返回的 operation id；受理后先做乐观更新，再由后台协程轮询操作终态。
  终态成功后只刷新当前窗口第一页；失败时回读已加载窗口以恢复被乐观移除／改写的项。
- 收藏不再在 202 之后立刻 GET 详情；图标立即切换，失败回退。标签／隐私状态按 mode 缓存 60 秒，
  标签写操作后失效，避免每次收藏都拉整份标签目录。
- 发送到另一模式在受理后先隐藏源卡片；失败通过操作终态恢复。批量操作期间返回键不再被长时间占用。

## 3. 上限与批次

- 移除选择、上传、下载、标签筛选、标签选择的 100 项上限；传输记录不再因 20 个批次拒绝新任务，
  已完成记录仍会自动收拢。
- 回收站／恢复由服务端 operations 队列逐项执行；上传、下载继续使用已有的持久队列，不再要求用户手动拆批。

## 4. 刷新与预取

- `refresh()` 只校准当前窗口第一页并按 id 合并，保留更深的已加载项；只有操作失败恢复时才回读整个窗口。
- 回前台不再按已加载条数线性发请求；下拉刷新、传输事件、发送完成都走同一条有界刷新。
- 图片、时间线、预取请求接受统一的取消对象；离屏模式页不再加载缩略图，只保留首屏元数据。
- 自动备份增加 5 分钟成功间隔，避免每次回前台都启动一次扫描。

## 5. 交互与搜索

- 搜索关键词或智能文件夹默认按相关度排序，服务端智能文件夹传 `smartFolderOrder=RELEVANCE`；
  日期排序仍可从“视图”选择。标签筛选增加“任一标签／全部标签”，并在条件胶囊上标明。
- 下载弹窗运行中可以“后台继续”，关闭不再取消；取消下载需二次确认；图库底部保留下载进度入口；
  启动下载前清理由进程死亡遗留的 `IS_PENDING` 行。
- 回收站大图提供“恢复”；自动备份失败行只重置该文件的失败检查点，表头仍可重试全部失败。
- 放大查看使用 4K 分享图作为有界高清层并缓存，缩回适屏不再每次重下整份原图；GIF／WebP 仍读原文件。

## 6. 后台任务与数据核对

- Android 14+ 的手动上传／下载改走用户发起的数据传输 Job（`NativeTransferJobService`），
  不再长期占用受 6 小时／24 小时限制的 dataSync 前台服务；旧系统仍回退前台服务。
- 整库扫描（含 7 天一次的完整对账）会把已正常备份项的 checkpoint 也纳入 `check-content-batch` 核对；
  增量扫描保留本地快速跳过，避免每次打开都发全库请求。
- 修复 `BackupService.onDestroy()` 中 `working` 先置 false 导致“备份未完成”状态永远不写入的问题。
- 备份传输页的快照改为有界：失败／上传中优先，完成项只保留最近 100 条；计数覆盖整轮，
  避免每 400 ms 复制并重排全部扫描行。
