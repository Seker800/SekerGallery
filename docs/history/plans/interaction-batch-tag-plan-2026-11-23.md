# 批量选择与标签交互整改计划

> 状态：已完成 | 日期：2026-11-23 | 对应提交：6a1c47b4
>
> 本计划只讨论交互改造与必要契约，不含排期。桌面端是同一套 Web UI 的 Electron 壳，
> 交互在 Web 层完成即两端同时生效；只有拖拽、缓存、连接属于桌面壳。
>
> 进展：15 项均已实现；`npm run ci:check` 通过；隔离工作台验证了选择全部匹配项、标签合并与
> 按所选永久删除。范围选择仍按已加载项，完整范围使用“选择全部匹配项”；桌面拖拽移除了
> 100 个硬上限，准备失败时提供“改为批量下载”回退，未用 100 个真实文件做原生拖拽验收。

## 1. 判断与设计基线

现有问题不是单个按钮缺失，而是三件事叠在一起：**批量选择选不全**、**创建动作离开当前上下文**、
**批量操作缺少可逆与反馈**。因此先立三条规则，后面 15 项都按它执行：

1. **不打断上下文**：能就地完成的创建/修改不跳页；要求跳页时，选择与输入必须保留。
2. **选择是一等公民**：选择跨页、跨工作区保持，规模由系统分批，用户不需要手动拆批。
3. **可逆优先**：可逆操作给撤销，不可逆操作给强确认和数量；异步操作有进度、取消、重试。

交互与视觉规范（所有新组件共用）：

- 沿用 `--ui-*` token、8px 栅格、32/36px 控件高度、Tabler 图标；不新增字体阶梯。
- 桌面 1440 宽、网页 1280 宽、窄屏 680 以下分别走查；暗色对比度不低于 4.5:1。
- 动效 120–160ms ease-out，尊重 `prefers-reduced-motion`；不做大面积 backdrop-filter。
- 选择数量、操作结果用 `aria-live="polite"`；所有对话框有焦点陷阱、Esc 关闭、关闭后焦点回触发器。
- 破坏性对话框统一组件：数量徽标、后果说明、危险色主按钮；不可逆操作要求输入确认词。

## 2. 选择模型（#1 #2 #3 #4）

### 2.1 目标体验

- 素材卡 hover/聚焦时出现 18px 复选框；单击卡片仍是选中，双击仍是查看（保持现有肌肉记忆）。
- 工具栏常驻“选择”按钮，不再依赖“先有选择才出现工具条”（现状是循环依赖）。
- 顶部/底部出现持久选择条：`已选 12 项`、来源说明（如“来自：标签「旅行」”）、主要操作、清除。
- `⌘/Ctrl+A`：第一次只选已加载项；选择条同时显示“选择全部 348 项”入口，点击后后台解析完整筛选结果，
  显示进度并可取消；解析期间禁止提交操作，取消时保留原有选择。
- Shift 范围选择基于完整结果顺序；跨页不要求两端都可见，只要在已解析的完整结果中即可。
- 切到标签页、任务中心、设置再回来，选择仍在；切换模式、进入回收站/私密、显式清除时清空，
  并给出短暂提示（可撤销只对误清空，不做跨模式恢复）。

### 2.2 实现要点

- 选择状态从页面级 `useReducer` 提升为按 `ownerId + libraryMode` 保存的工作区状态；记录来源筛选描述，
  供选择条显示与“返回原视图”。
- 新增只读解析接口 `POST /eagle/assets/selection`（请求体复用现有 `EagleAssetFilters`，返回
  `{ items: [{ assetId, rowVersion }], nextCursor }`）。必须复用现有列表查询构造与可见性规则，
  不另写一套筛选；owner 来自认证主体，模式来自控制器，PHOTO 空继承自动获得。
- 客户端按 1000/页累积，AbortController 取消，内存约为 6 万条 × 几十字节；操作仍走现有
  `assetIds + rowVersion` 协议，不新增写入口。
- 快捷键放在独立的 `useLibraryShortcuts`：输入框/可编辑区域内不拦截；`?` 打开快捷键面板。
  建议映射：`⌘A` 全选、`Esc` 清除、`Space` 快速预览、`Enter` 预览、`Delete` 移入回收站（可撤销）、
  `0–5` 星级、`T` 标签、`F` 收藏、方向键在网格内移动焦点。
- 删除改为“移入回收站 + 撤销 toast”，撤销走 RESTORE；不再弹系统 `confirm`。

### 2.3 选择条与卡片

- 选择条高 44–48px，吸附在工具栏下方；为它预留布局空间，不覆盖卡片。
- 主操作最多 3 个（标签、星级、更多），其余进 overflow；移动端改为底部条。
- 卡片选中态用 2px 强调色内描边 + 勾选角标，避免整卡减淡导致图片难辨认。

## 3. 标签体系（#0 #5 #6 #7 #8 #9 #14）

### 3.1 统一“新建标签”组件

做一个可复用的 `TagComposer`（名称 + 可选颜色 + 可选标签组，Enter 提交、Esc 收起），
在批量标签对话框、标签页、按标签筛选中共用。默认只填名称，颜色/组折叠在“更多”里，
不拖慢高频路径；创建成功后自动勾选/定位并高亮。

批量标签对话框改为：

- 空查询时顶部常驻“新建标签…”行；
- 有查询且可创建时显示“创建「x」”（即使存在相似标签，只要不是同名或纯拼音命中）；
- 纯拼音命中的查询仍不提供创建，避免造出 `yjfw` 这类标签；同名时直接勾选已有标签；
- Enter 创建、⌘Enter 应用；创建后输入框清空，可连续新建；
- 列表分“全部/最近使用”，左侧增加标签组导航与计数；标签行显示“已应用 x/N”，不再只是库内总数。
- 新建标签不再要求先离开对话框，因此“绕去标签页再回来”的路径消失。

### 3.2 标签页

- 选择跨分页保留，翻页不再清空；选中数量常驻在工具栏。
- “全选当前筛选”直接在前端完成（标签列表本就全量加载），支持跨页 Shift。
- 增加合并：选中 2 个及以上标签 → “合并…” → 选目标标签 → 预览“将合并 N 项素材、删除 M 个标签”
  → 确认。目标标签保留名称/颜色/组，源标签素材并入后删除源；系统标签、被智能文件夹引用的标签、
  私密规则标签在预览阶段明确拦截并说明原因。
- 颜色：每个标签/标签组提供色板 + 自定义 + 清除；批量选中后可一次设色。颜色在标签页、批量对话框、
  筛选器中一致显示。
- “移动到标签组”下拉增加“新建标签组…”内联创建，不再要求先去侧栏建组再回来。
- 新建/重命名/合并成功后定位到目标并短暂高亮；请求失败时保留编辑条与输入，内联报错。

### 3.3 合并的服务端边界

- 新增域命令 `TAG_MERGE`（沿用现有命令注册与操作队列）：按源标签关联的素材分批“加目标、去源”，
  结束后删除源标签；整批进度、失败可重试、幂等。
- 复用 `EagleAssetOperationService` 的批次领取与 `publishMetadataBatch`，不新增第二套写入/权限/租约。
- 合并前统计素材数、隐私影响、智能文件夹引用；不可撤销时在确认框明确写出。
- 与标签批量添加/删除共用同一事务规则；批次大小按现有数据库批处理常量，不按“安全”名义给用户加配额。

### 3.4 误点与撤销（#8）

- 已选素材上的标签 chip 不再单击即删：改为 chip 右侧显式 `×`（hover/聚焦显示，触屏常显）。
- 点击 `×` 后立即执行，同时出现 8 秒撤销 toast：“已从 12 项素材移除「旅行」· 撤销”；
  撤销用同一批量命令反向加回，带 predecessor 处理并发冲突。
- “清空所有人工标签”保留确认（一次性影响面大），确认文案带素材数与标签数。

## 4. 照片组（#10）

- 时间线工具栏增加“照片组：折叠 / 展开”开关，按 owner+模式记住偏好；展开后成员直接出现在网格中。
- 选择语义：折叠状态下单击组封面选中整组，⌘/Ctrl 单击只选封面；选择条显示“3 组 / 12 张”。
- 组内大图增加“选择整组”“为整组加标签”“整组收藏”；标签选择器接收组成员 ids，复用批量标签。
- “取消分组”改为可撤销 toast：底层 `dismissed: true/false` 已支持，撤销即恢复分组，不新增接口。
- 不新增独立组管理页；人工建组/合并仍走既有 API，界面先只补“撤销取消分组”和整组操作。

## 5. 桌面拖拽（#11）

- 去掉“超过 100 个直接报错”。拖拽开始时若数量较大，弹层显示数量、总大小、预计准备时间级别
  （“较大/较慢”而非承诺时长），提供两条路：
  1. **继续准备全部**：后台流式准备，显示进度、可取消，完成后开始原生拖拽；
  2. **保存到文件夹**：一次动作把整批原文件保存到用户选择的目录。
- 主进程按现有并发/限速分批下载到临时目录，检查临时盘剩余空间；空间不足时明确提示并给文件夹方案。
- 取消/失败清理已准备文件；临时目录 TTL 与现有 1 小时策略保持一致。
- 不静默只拖前 100 个，也不要求用户自己拆批。

## 6. 边界与一致性（#12 #13 #15）

### 6.1 发送到另一模式（#12）

- 菜单项常显；不可用时禁用并给出具体原因（“含 2 个视频/音频”“3 项仍在处理中或处理失败”
  “部分所选尚未加载”等），点击或悬浮显示原因，不再整项消失。
- 是否允许“只发送可用项”留作产品决策；默认不做部分发送，避免用户误以为全部已发送。

### 6.2 智能文件夹（#13）

- 搜索/筛选区常驻“保存为智能文件夹”，打开时带入当前快捷筛选，并把搜索词预填为
  名称或描述包含规则（两者任一命中）；名称默认取搜索词。
- 对话框明确说明“文件名、标签名和画面相似匹配不会被默认保存”，并提供可选的
  “同时保存画面相似条件”勾选；勾选后写入一条 SEMANTIC 规则，匹配范围在规则编辑器内调整，
  默认平衡，创建后由后台生成快照。画面搜索不可用时仍允许保存并提示后台重试。
- 不带搜索词的纯筛选保存不显示上述提示与勾选。
- 保存后留在原视图，选择与滚动位置不变。

### 6.3 回收站永久删除所选（#15）

- 回收站选择条与右键菜单增加“永久删除所选”；对话框显示数量、占用空间、“不可恢复”，
  要求输入确认词（小批量也输入，保持一致）。
- 服务端新增不可逆命令：为目标标记 `purgeAfter`，由现有清理任务删除对象；进度与结果可见，
  失败可重试；写审计记录，不暴露对象键。
- 保留“清空回收站”；两者共用同一清理执行路径，不新增第二套删除逻辑。

## 7. 共享组件与视觉

新增/改造组件（均沿用现有 token 与图标）：

| 组件                  | 用途                       | 关键规格                              |
| --------------------- | -------------------------- | ------------------------------------- |
| `SelectionBar`        | 选择计数、来源、操作、清除 | 44–48px，sticky，移动端底部           |
| `TagComposer`         | 新建标签/组                | 名称必填，颜色/组折叠                 |
| `TagPicker`           | 批量加/删标签              | 760×640，左组导航 + 右列表 + 最近使用 |
| `TagMergeDialog`      | 合并预览                   | 420px，数量、隐私、引用阻塞           |
| `DangerConfirmDialog` | 永久删除/清空              | 焦点陷阱，输入确认词                  |
| `UndoToast`           | 撤销                       | 8s，最多 3 条，hover 暂停             |
| `ShortcutHelp`        | 快捷键面板                 | `?` 打开，分组列出                    |

- 视觉层级：选择条用 surface-2 + 1px border + 柔和阴影，不用强对比遮罩；主按钮只有一个。
- 标签对话框保持现有暗色风格，新增左组导航使用低饱和底，选中组用强调色细边，不做大面积色块。
- 行高统一 40px，分组标题 28px，间距 8/12/16；窄屏折叠为单列，最近使用改为分段控件。
- 所有空态给一个明确主操作（如“新建第一个标签”），不出现只有说明文字的空白页。

## 8. 服务端、契约与成本

新增面只有三处，且都复用现有协议：

1. `POST /eagle/assets/selection`：只读、分页、id+rowVersion、与列表同源筛选；双模式空继承；
   owner 由主体推导；隐私与私密可见性规则与列表一致；无写入口。
2. `TAG_MERGE` 命令：走 operations 队列与命令注册；批次内加/去标签，结束删源；进度/重试/幂等；
   被智能文件夹引用时拒绝并说明。
3. 永久删除所选：标记 `purgeAfter` 的不可逆命令 + 现有清理任务；审计记录，不返回对象键。

成本要求（按 `docs/performance-budget.md` 口径）：

- 全选 6 万条：解析接口 60 次 1000 行请求，客户端累计；操作入队仍是一批，内部按现有常量分批。
- 合并 1 万条关联：只涉及数据库，无 S3；给出批次数、事务数、唤醒次数。
- 永久删除 100/1000 条：一次标记 + 清理任务按批删除，给出对象删除与 outbox 数量。
- 新增接口必须补跨 owner 404、私密过滤、双模式契约与架构门禁反例测试。

## 9. 验证与回归

- 组件测试：创建条件（同名/相似/拼音/超长）、键盘、选择跨页、撤销、合并预览、永久删除确认。
- 集成测试：真实数据库验证合并幂等/部分失败、选择接口与列表结果一致、私密与跨 owner、永久删除清理。
- 真实端：网页 + 桌面构建后走主路径与边界——全选 500、取消解析、跨页 Shift、合并 2 个标签、
  误点撤销、展开照片组并整组加标签、拖 300 个原文件、永久删除少量、快捷键在输入框内不误触。
- 性能：6 万条全选解析、1 万条合并、批量标签刷新次数；与现有预算对照。
- 视觉：1440/1280/窄屏暗色截图对照；焦点环、对比度、读屏计数。
- 门禁：`npm run architecture:check`、共用契约测试、lint/typecheck/test/build；桌面改动实际启动客户端。

## 10. 依赖顺序与待拍板

按依赖顺序做，不做时间承诺：

1. 选择模型与全选（#1 #2 #3 #4）+ 选择条，这是后面所有批量操作的地基。
2. 标签重建（#0 #5 #6 #7 #8 #9 #14）与合并命令。
3. 照片组（#10）、拖拽（#11）、发送提示（#12）、智能文件夹入口（#13）、永久删除（#15）。
4. 统一视觉、快捷键面板、无障碍与性能收尾。

需要你拍板的点：

1. 选择是否跨“标签页/任务中心/设置”保留（建议保留；切模式、回收站、私密时清空）。
2. 合并标签是否必须可撤销（建议确认 + 不可撤销；要撤销需保存关联快照，成本明显更高）。
3. 回收站是否开放“永久删除所选”（建议开放，强确认 + 审计）。
4. 智能文件夹从搜索保存（已按建议实现）：默认保存名称/描述与当前筛选，画面相似作为可选勾选；
   勾选后写入 SEMANTIC 规则，范围在规则编辑器调整。
5. 拖拽超过上限时默认“继续准备”还是默认“保存到文件夹”（建议弹层二选一，不设默认静默行为）。

## 11. 不做的事

- 不新增第二套写入路径、权限、租约或事务编排；批量能力继续复用 operations 队列。
- 不引入文件大小/数量预拒绝，不按“安全”名义把批量拆给用户。
- 不改照片组、私密、系统标签的既有数据语义；颜色/合并只作用于人工标签。
- 不为移动端单独做一套交互；窄屏复用同一组件降级。
